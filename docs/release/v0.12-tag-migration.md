# ma-browser v0.12.0 tag migration plan

Status: plan only. This M2 change does not delete, force-move, or push any tag.

The existing local `ma-browser-v0.12.0` tag is an annotated historical tag at
commit `ac3ba54`. It predates the current security branch and must not be
treated as the release tag for the M2 result. The release commit must first
contain the unified `0.12.0` version, the README/MCP configuration updates, and
the C1–C3 adapter safeguards.

Before publishing v0.12.0:

1. Select the final release commit on `main` and verify the package, Cargo,
   Tauri/About, generated MCP config, and portable zip all report `0.12.0`.
2. Confirm the release assets and checksum are ready. Portable packaging is an
   M3 activity and is not performed by this change.
3. With explicit release-owner approval, inspect the remote tag and decide
   whether the historical tag may be retired. Do not use `git tag -f` or
   `git push --force`.
4. If tag relocation is approved, delete the old local/remote ref explicitly,
   create an annotated `ma-browser-v0.12.0` tag at the selected release commit,
   and push only that tag. If relocation is not approved, retain the historical
   tag and publish under a new approved tag instead.

Suggested dry-run checks (do not execute the mutation commands automatically):

```bash
git show --no-patch --format='%H %D' ma-browser-v0.12.0
git diff --check <release-commit>^ <release-commit>
git tag --points-at <release-commit>
```

The tag migration is intentionally separate from M2 so this branch cannot
rewrite shared release history.
